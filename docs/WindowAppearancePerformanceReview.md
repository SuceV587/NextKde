# 窗口外观与动画：资源和性能审阅

日期：2026-10-10。静态审阅范围为当前参与构建的 Bridge 外观模块、Glass，以及 Dock／Stage 动画的资源和定时器路径。未编译、运行、安装、热重载或采集 CPU／GPU／内存数据；以下区分源码中确认的问题与尚未量化的代价。旧的 `contourclip/appearancerenderer/appearanceshadow` 未参与构建，不作为当前运行路径。

## 本轮确认并修改

| 优先级 | 原来的触发与代价 | 修改 |
| --- | --- | --- |
| 高 | `AppearanceConfig::load` 每次成功读取都发 `changed`；同目录其他文件变化、重复 reconfigure、文件与目录的重复通知，即使配置内容没变，也清空所有圆角纹理并请求全屏重绘。读取／解析失败同样触发失效。 | 合并 20 ms 内的文件通知；相同有效文件内容直接返回；失败保留原配置和缓存；文件删除只在从自定义配置切回默认值时通知一次。窗口明暗仍由原生 `paletteChanged` 更新。 |
| 高 | `dirtyTiers` 在每次几何信号中同步遍历所有窗口；每个窗口又读取／筛选一次堆叠列表。拖动过程中可能多次进行重复的两两重叠计算。 | 同一事件循环内合并通知；一份堆叠快照从上向下计算，共享已筛选的窗口矩形；只更新层级变化的窗口。互不重叠的大量窗口仍有最坏 O(N²) 矩形比较，未宣称彻底消除。 |
| 高（启用 Glass 动态圆角时） | 普通窗口每次移动调用 `repaintDynamicCorners`，直接请求所有输出全屏重绘。 | 只重绘接受 Glass 动态圆角的可见 Dock／菜单／弹出窗口；不再因这一功能请求全屏重绘。统一外观已接管的窗口跳过。背景特效仍按自身需要扩展局部损伤。 |
| 中 | 圆角内容纹理最小化后保留至窗口关闭，长期占用 256 MiB 预算，挤占其他窗口的连续圆角名额。属于缓存保留，而非没有释放路径的永久泄漏。 | 监听实际场景节点的 `visibleChanged`，排队检查最终可见性，不可见时释放纹理和预算。动画可见引用仍使节点可见时保留；用 `QPointer` 防止排队回调访问已删除窗口。 |
| 中 | 阴影图集在 32 MiB LRU 中被淘汰或单个图集超过缓存成本后，下一次绘制可能重新生成同一图集，即使窗口正在使用它。 | SSD/CSD 状态持有当前图集；缓存增加弱引用查询，复用仍被窗口持有的图集。分配时清理过期弱引用，避免持有所有历史几何版本。32 MiB 是 LRU 保留上限，不包括正在使用的图集与 GPU 纹理。 |
| 中 | `m_resolved` 对没有规则的每个历史 window class 都缓存一份相同默认值，窗口关闭不删除这份配置。 | 无应用规则直接返回默认值；合并结果只缓存当前配置中有规则的应用键，数量不再随历史窗口类别增长。 |
| 中 | 每次连续圆角绘制按名称设置 10 个 uniform；KWin 的按名称接口直接调用 `glGetUniformLocation`。 | shader 初始化时查询一次位置；绘制时使用整数位置。另外明确检查 shader 是否有效，失败回退为原生圆弧。 |
| 中 | Glass 装饰器变化时创建新的 blur 信号连接，却没有保存／断开旧连接；重复注册窗口也可能覆盖已有连接句柄。旧装饰器尚未销毁时可能重复更新或保留引用原窗口的回调。 | 保存每窗口的装饰器连接；切换时先断开旧连接；窗口删除时断开；已注册窗口不重复注册。常规 QObject 析构自动断开的路径仍保留。 |

上述修改不包括上一轮已经调整的动画效果链位置，以及活动／后台阴影缓存边距固定；它们仍是本次性能分析的前提。

## 未发现明确永久泄漏的路径

- Bridge 的窗口状态在 `windowDeleted` 删除；场景子节点同时设置 QObject 父对象，关闭外观／卸载时主动恢复并删除。动态阴影定时器到期停止，不是常驻 60 Hz 定时器。新增层级及配置定时器均为单次。
- 连续圆角的重定向在窗口删除、配置变更、能力／预算回退、节点隐藏和析构时释放；`OffscreenEffect` 自身也有窗口删除与损伤连接的清理路径。
- Dock 动画结束会 `unredirect`、移除动画、释放可见引用和效果所有权；窗口删除清理相关表；开窗尝试有次数上限和 `QPointer`，不无限重试。动画存在时的重绘和变形屏幕标志有明确用途。
- Stage 卡片释放会撤销离屏渲染引用、断开损伤连接、释放 FBO／纹理；卡片清空时停止 33 ms 帧钟。当前源码在不支持内容渲染时关闭原生活体卡。支持它的版本有卡时继续喂帧和渲染是功能成本；8 s 状态钟与 10 s 文件重读钟仍常驻，零卡时不应误判为 30 Hz 渲染泄漏。
- Glass 的输出移除、窗口删除会清除对应渲染资源。SurfaceShapeManager 卸载时暂留的 Wayland 资源由客户端持有，回调被断开，资源由客户端 destroy／断开连接清理，不能简单当作遗失的堆内存。

这些是源码生命周期判断，不能代替长时间运行后的实测结论。

## 仍然存在的性能代价

1. **内容损伤后整窗重绘**：KWin `OffscreenEffect` 只保存“是否脏”，一个小区域损伤也会重绘整个离屏窗口。视频、滚动、输入频繁更新的窗口会持续付出额外渲染和带宽成本。
2. **动画双缓存**：现在顺序正确，但连续圆角与 Dock／Stage 动画仍各有自己的缓存。256 MiB 预算只计 Bridge 新增纹理，不是整个 KWin 显存上限；Glass 的模糊链与动画纹理另计。静止窗口可复用，持续更新窗口仍可能经过两层绘制。
3. **透明窗口参与合成**：连续圆角必须让切掉的角看到后方内容，目前通过整窗 translucent 标志实现。重叠窗口／全屏可能增加后方合成成本。不能直接删掉标志，否则容易重新出现黑角；部分不透明区域的保留需要进一步设计。
4. **原生图集与界面控制的热路径**：圆弧模式每次准备仍生成图集键字符串，Bridge 按钮的遮挡处理仍逐窗口走堆叠列表。都可继续缓存，但必须覆盖缩放、装饰器、几何、可见性和规则变化，避免留下错误的视觉缓存。
5. **动态内容仍是主要瓶颈候选**：后续最值得评估的是让动画使用已有离屏层完成圆角，减少重复缓存／采样；涉及动画坐标、圆角距离场和 KWin 颜色转换，应作为独立改动处理。这一轮没有做结构重写，也没有性能提升百分比。

## 交给用户的验证

本轮修改 `kos-bridge` 和 `glass-effect`，需重建安装这两个组件并注销登录；没有修改 Dock、Stage 或 decoration 源码，也没有自动改用户配置。此前连续圆角集成若尚未安装，仍需先安装相应 decoration 版本。完整外观与动画判定见 [WindowAppearanceVerification.md](WindowAppearanceVerification.md)。

1. **空闲基线**：启动桌面，等阴影／窗口动画结束。用系统监视器或 `top` 观察 `kwin_wayland`，分别静止 1 分钟、5 分钟。不要以 `ps %CPU` 的进程生存期平均值代替当前负载。Stage 实时卡、视频、动态壁纸要分别记录，不能混入“纯静止”基线。
2. **重复开关**：Dolphin／Kate 与 Firefox／Electron 各开关约 20 次，每批结束等待一分钟，观察 CPU 回落和内存是否趋于稳定平台。RSS 只覆盖进程驻留内存；GPU 驱动保留的纹理分配未必立即降低 RSS，不能用一次没有回到最初值判定泄漏。
3. **缓存释放与动画**：几个大窗口逐个最小化，等待动画结束，再逐个从 Dock 还原；动画中途反向点击也要试。检查没有第一帧冻结、黑角或突然消失，还原后圆角恢复。显存监测如果驱动支持，可观察隐藏窗口缓存释放后的趋势；不要把整个 KWin 显存要求为 256 MiB。
4. **配置无变化**：保持外观配置内容相同，保存同一文件或修改同目录其他设置。窗口不应因这一步闪烁／突然卡住；真正更改圆角仍应热生效。临时写入非法 JSON 应保持上一份有效外观；随后恢复有效内容再检查。
5. **多窗口拖动**：5 个、15 个窗口，拖动一个窗口靠近／远离其他窗口。检查后台阴影层级仍随实际重叠更新，鼠标停下后没有持续重绘。大量互不重叠窗口若仍明显增加 CPU，记录数量；最坏 O(N²) 比较还存在。
6. **Glass 动态圆角**：开启 Glass 现有的动态圆角选项，把应用移动到 Dock／菜单的相邻边，再移开。检查局部圆角更新、模糊背景和旧位置清理正常；跨输出也重复。重点排除局部重绘替代全屏重绘后的残影。
7. **分离额外渲染成本**：相同窗口、相同配置，比较静止／滚动／视频，分别使用 `arc` 和 `continuous`。如果仅连续模式的动态内容卡，优先怀疑整窗离屏更新成本；这不是本次缓存释放修复能全部解决的问题。

## 后续优化与社区实现对照（2026-10-10）

本节继续回答“缓存还有什么优化、社区怎么做”。仅静态审阅和远程源码读取，没有编译、安装、运行或性能采样，没有改动渲染实现。

### 社区方案的实际边界

- [KDE-Rounded-Corners 当前 Effect.cpp](https://github.com/matinlotfali/KDE-Rounded-Corners/blob/master/src/Effect.cpp) 同样继承 OffscreenEffect，调用 redirect/setShader/OffscreenEffect::drawWindow。其 Shader.cpp 在初始化时缓存 uniform 位置。支持 squircle 不意味着可以省掉整窗纹理；README 的历史优化说明不能解释成当前 Qt6 路径完全没有离屏绘制。
- 该项目提供 markWindowsTranslucent 开关，源码明确说明整窗透明会让 KWin 绘制后面的内容。旧版本分支减掉四角的不透明区域；6.6.80 之后不执行这段旧接口逻辑。当前本机 WindowPrePaintData 只有 mask 和 setTranslucent/setTransformed，不能照搬 data.opaque/deviceOpaque 修改。
- [LightlyShaders](https://github.com/a-parhom/LightlyShaders/blob/master/src/lightlyshaders/lightlyshaders.cpp) 同样采用 OffscreenEffect。其四角 opaque 区域处理使用旧 API；适合作为轮廓和遮挡处理的参考，不能直接承诺适配本机 KWin。
- [KWin v6.7.5 OffscreenEffect](https://github.com/KDE/kwin/blob/v6.7.5/src/effect/offscreeneffect.cpp) 的 maybeRender 只用一个 dirty 标志。内容损伤后清空整张 FBO，再以 Region::infinite() 绘制。原缓存已有静止复用；单纯扩大预算不能消除动态内容的额外带宽。

### 建议的实施顺序

1. **合并 Dock 动画与圆角的离屏层**。现在两者独立持有 OffscreenEffect 缓存。目标是在动画期间由 Dock 的同一份源纹理承担内容，最终变形绘制一起应用连续轮廓、描边和阴影。必须传递未变形的窗口局部坐标，不能用变形后的屏幕位置计算圆角；还要覆盖动画反向、跨缩放输出、颜色转换和动画结束后的所有权交接。不能仅在动画期间关闭 Bridge 裁剪，那会让圆角跳回直角。预计首先减少重复纹理及动态内容的重复绘制；静止窗口本来就复用缓存，收益需区分。
2. **保留中心的不透明遮挡区域**。仅四角和外侧阴影需要透出后方；整窗透明可能放大重叠窗口、视频壁纸等场景的合成成本。这需要场景不透明区域或 KWin 渲染层支持，当前效果 API 不能直接照搬旧项目的 opaque 字段。保持客户端本来的透明区域；变形、窗口半透明和模糊等情况须保守处理。禁止简单删除 setTranslucent，避免重新出现黑角。
3. **缓存轮廓与阴影的小图集**。对当前半径、smoothness、物理缩放、描边宽度及阴影参数生成四角/八片资源，窗口直边拉伸复用。连续模式目前在 shader 中实时计算 pow/exp；小图集可减少边缘算术，也可减少把外侧阴影边距计入内容缓存的机会。但增加纹理采样未必更快，收益应先比较；仅缓存 mask 仍不能避免整窗内容离屏绘制。动态阴影适合保留活动/后台两套资源，通过有限动画混合，而非每帧生成图片。
4. **持续缩放时减少重新分配**。KWin 当前纹理按精确尺寸分配；每个尺寸变化都可能分配。自定义缓存可采用容量分档，另存有效尺寸、UV 和内容原点，在手势结束时收紧。代价是显存增加；必须按实际容量计预算，清理无效边缘，正确处理尺寸跨档与输出缩放。仅增大 256 MiB 上限不会改变精确尺寸重分配。
5. **最后才设计离屏局部损伤**。保存窗口损伤区域，映射到 FBO，仅清理/重绘对应区域，尺寸、缩放、装饰器及效果变化时完全失效。当前 OffscreenEffect 未暴露这种更新能力，需要独立缓存实现或 KWin 上游改动。滚动、视频可能仍损伤大部分区域；透明混合、模糊扩散和坐标变换使这项风险最高。

优先级针对之前反馈的最小化/还原卡顿，而非未实测的提升百分比。整窗离屏缓存、后方合成与 Glass 背景模糊是不同成本：背景变化时不能长期复用旧模糊图，否则会冻结或产生残影。对玻璃适合继续缩小损伤范围、按模糊核扩展边界、复用中间 FBO；持续变化的背景仍需更新。
