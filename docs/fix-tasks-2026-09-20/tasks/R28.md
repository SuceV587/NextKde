## 问题
`shell/desktop/modules/platform/PlatformClient.qml`（357 行）与 `DataClient.qml`（324 行）是**几乎逐行重复**：socket 路径、readOperations 集合、有无 `requestTimeoutOverrides` 之外逻辑相同。修一处的 dedup/超时 bug 极易忘同步另一处。整套 IPC 客户端（断线/超时/半包/dedup/重连）**零测试**——daemon 重启时最可能产生真实用户可见 bug 且无护栏。
另：`file.transfer`/`screenshot.capture`/`file.copy`/`file.empty-trash` 的 client 超时设 0（永不超时），但 daemon `runCommand` 30s watchdog 会杀它——两端语义漂移需对齐。

## 改动点
- 抽 `JsonlClient.qml` 基类/工厂，两单例只剩 `socketPath`+op 表+overrides。
- 对齐永不超时 op 的两端语义（要么 daemon 这些 op 也放宽，要么 client 给有限值）。
- 新增 `platform/tests/` 下 mjs 测试：断线重连、超时回调、半包、超大行、dedup 合并。
- `_expireRequests`/dedup 边界（`_queuedByKey` stale key）补覆盖。

## 验证
- 新测试全绿；`qs -p shell` 实测 daemon 重启后各服务恢复。
- 两 client 行为与合并前一致（无回归）。

## 审查要点
- 基类抽象不破坏两 client 各自差异点（timeout overrides、read 集合）。
- dedup/超时的边界条件测试覆盖到位。
