# KOS 统一窗口外观开发方案

状态：开发方案，已部分实现。日期：2026-10-10。当前连续轮廓及原生圆弧实现、已知限制及交给用户的验收步骤见 [WindowAppearanceVerification.md](WindowAppearanceVerification.md)；本轮按用户要求未编译或运行验证。

## 1. 目标与交付范围

通过现有 `kos-bridge`、`kos-decoration`、Glass 和 `kos-settings`，统一普通应用窗口及其对话框的圆角、外框、描边、阴影和焦点变化效果，不再依赖独立的 Rounded Corners 特效。

用户从 `kos-settings` 配置：

- 圆角半径和曲线形状，支持接近 iPadOS 的连续圆角视觉。
- 外框档位：无、小边框、粗边框；高级设置允许调整各档宽度。
- 默认外框颜色跟随明暗主题；应用可以覆盖颜色、尺寸及其他细节。
- 激活窗口阴影最深，后方可见窗口随堆叠层级逐步减淡，并平滑过渡。
- 内容保护策略，避免未经设计的直角应用被圆角裁掉重要内容。
- 每应用覆盖、恢复继承、最大化／全屏／平铺策略。

范围中的“统一”指统一外部窗口轮廓与层次，不承诺改写应用内部工具栏、布局、字体或应用自己的控件。桌面、Dock、通知、输入法、菜单等特殊表面继续遵循各自的外观系统。应用自绘标题栏保留其内容，现有统一按钮覆盖行为继续适用。

## 2. 已核实的项目基础

| 组件 | 当前基础 | 需要补充的能力 |
| --- | --- | --- |
| `kwin/kos-bridge` | 同时给系统装饰和自绘装饰窗口绘制统一按钮；应用规则、焦点通知、遮挡计算 | 整个窗口的曲线、描边和阴影策略；生命周期恢复；动画兼容 |
| `kwin/kos-decoration` | 系统标题栏、文字、边界和缩放区域；当前主动不设置圆角／描边／阴影 | 内容保护外框、原生装饰阴影及统一配置接入 |
| `kwin/glass-effect` | 背景模糊／折射；超椭圆形状；部分路径调用 `setBorderRadius()` | 服从统一轮廓，避免再次覆盖普通窗口半径 |
| `apps/settings` | 独立应用，通过桥接与 Shell IPC 配置；已有主题与外观页面 | 窗口外观页面、应用覆盖编辑、预览、状态和错误反馈 |
| `platform` | 配置读写、JSONL 事件、KWin D-Bus 操作 | 窗口外观配置操作、修订号、运行能力与插件状态 |

KWin 当前头文件提供 `stackingOrder()`、`stackingOrderChanged()` 和离屏窗口绘制接口。原生 `BorderRadius` 只有四角半径，不能直接表达可调连续曲线。连续轮廓需要自定义绘制路径或扩展能力，不能把原生半径接口等同于完整方案。

## 3. 总体架构

```text
kos-settings：编辑、预览、应用覆盖
       │ 项目已有 IPC / 平台调用通路
       ▼
kos-platform：校验、原子持久化、配置修订与状态
       │                       │
       ▼                       ▼
统一 WindowAppearance 配置与解析模块
       │                       │
       ▼                       ▼
kos-bridge                  kos-decoration
窗口策略、连续曲线           标题栏、真实外框留白
描边、动态层次、CSD处理       原生装饰几何与阴影
       │
       ▼
Glass：遵循同一窗口轮廓，绘制背景材质
```

`kos-bridge` 是统一外观策略的管理者；其他组件执行各自负责的渲染和布局。配置和曲线定义只有一份，不允许装饰器、Glass、桥接插件各自决定不同圆角。

系统装饰窗口优先使用 KWin／KDecoration 的布局和阴影机制。需要连续轮廓时，由统一曲线模块提供裁剪和匹配的描边／阴影形状。原生圆形裁剪不得同时截掉自定义曲线保留的像素。

自绘装饰窗口由 `kos-bridge` 处理。现有按钮渲染与新增窗口外观模块分开：关闭按钮或调整按钮位置，不应关闭窗口圆角和阴影。不得把整个功能绑定到 `showButtons` 或按钮动画隐藏分支。

## 4. 内容保护：正式实现前必须通过的验证

### 4.1 外框、描边、安全留白是不同概念

- 外框宽度影响窗口外壳布局。
- 描边是轮廓上的细线，不足以容纳被圆角切掉的内容。
- 安全留白保证完整的矩形内容落在曲线内部，所需大小取决于半径与曲线。

“无边框”不能隐含“完整内容保护且窗口尺寸完全不变”。如果没有额外空间，直接圆角裁剪必然可能移除角落像素。设置页必须明确说明所选模式的效果。

### 4.2 内容模式

| 模式 | 行为 | 适用与限制 |
| --- | --- | --- |
| `protect` 保护内容 | 增加真实外框／足够安全留白，完整内容保持原比例和输入坐标 | 系统装饰窗口可利用装饰布局；自绘窗口必须验证实现路径 |
| `compact` 紧凑裁剪 | 原有窗口大小保持，直接套统一曲线 | 可裁掉角落内容；用户明确选择或应用覆盖使用 |
| `preserve` 保留原轮廓 | 保留应用原来的裁剪，应用可用的描边／阴影 | 作为无法安全保护时的明确兼容策略 |

对系统装饰窗口，验证装饰器增加四边留白、顶部标题栏、缩放范围和窗口大小协商。不要只在屏幕上画一个外框而不更新实际几何。

对自绘窗口，验证当前 KWin 是否可以给这类窗口附加有效外框及正确边界。Shadow-only 装饰模式的存在不等于支持任意外框留白。若只允许特效绘制外部区域，必须验证：工作区约束、平铺、鼠标命中、遮挡、阴影损伤区域、截图和动画是否一致。

禁止用整体缩小应用纹理冒充内容保护：这会改变清晰度、视觉大小和点击位置，若没有配套输入映射则会点击错位。禁止将像素颜色猜测作为自动判定“角落可以裁掉”的可靠依据。

应用自己画在纹理中的透明边距、阴影和圆角必须识别处理。协议提供的边距可使用；缺少可靠信息时支持应用规则手动指定，不能承诺自动去除所有自绘阴影。

如果自绘窗口的无损外框不能在现有插件接口内成立，应在验证报告中说明需要 KWin 修改或应用配合，并明确列出支持范围。此时不得宣称“所有应用无损统一”已完成。

## 5. 圆角与曲线

配置分开表示半径和曲线，UI 提供“圆弧”和“连续圆角”预设及连续程度调节。

实现共享 `WindowContour`：输入逻辑坐标、外轮廓、四角半径、曲线参数、缩放、内容安全矩形；输出裁剪、描边、阴影共用的轮廓。GPU 和离线预览使用同一算法定义。可从现有 Glass 的超椭圆公式起步，但应通过样张评审后确定连续圆角的具体曲线，不能声称等同于 Apple 私有曲线。

半径根据窗口尺寸钳制，处理极小窗口、四角不对称、分数缩放与多屏 DPI。抗锯齿在设备像素空间正确计算，预乘透明度处理一致。圆角外的区域不得错误参与不透明遮挡，否则窗口后面的图像可能缺失。

当前源码默认半径 20 个逻辑像素、连续程度 0.6；连续模式使用 KWin 损伤驱动的窗口内容纹理缓存和同一着色器绘制三层轮廓，圆弧模式保留原生节点。连续模式新增 GPU 纹理预算 256 MiB，超限或能力不支持会记录原因并回退为原生圆弧。默认值及性能仍由用户验收。这些是待预览确认的产品默认值，不作为技术限制。

## 6. 动态阴影

读取真实堆叠顺序，使用窗口焦点和遮挡关系推导视觉层级；不把堆叠索引称为真实三维 Z 坐标。

候选集合排除最小化、不可见、非当前桌面和特殊表面；按输出及可见重叠关系分组。跨屏窗口分别处理可见区域，独立且不重叠的窗口不因全局堆叠序号被无意义地弱化。瞬态对话框和所属应用保持合理的层级关系。

默认使用三层结构：内侧细描边、外侧窄贴边阴影、宽范围柔和扩散阴影。贴边层分离重叠窗口，扩散层表达悬浮高度，避免明显黑圈。初版采用有限档位：激活窗口、第一层后台、第二层后台、远处后台；活动窗口扩散阴影更深、更宽，后台逐级减弱。只动画化描边与阴影透明度，不改变窗口内容的不透明度。宽度先立即切换，透明度做有限过渡。

建议默认过渡约 180 ms，降低动态效果设置时立即切换。焦点与堆叠事件更新目标值，有限动画到期停止；优先使用 DecorationShadow、原生描边与 KWin 场景节点的损伤机制，不逐帧截图、不采样背景、不持续重绘。阴影以共享的小型八片纹理缓存，尺寸变化只调整直边几何。

阴影缓存按尺寸可复用的形状、半径、曲线、缩放与软度建键，强度尽量用绘制调制。原有原生阴影与新阴影必须明确择一，禁用时恢复。无法去除的内容内置阴影应暴露应用兼容规则，避免静默双重阴影。

## 7. 边框档位与主题颜色

默认内侧描边以 1 个物理像素为目标，HiDPI 与分数缩放时换算逻辑宽度，并与圆角共同对齐设备像素。深色窗口用低透明度白色、浅色窗口用低透明度黑色；根据窗口声明的调色板选择，不实时采样壁纸。无法正确声明外观的 CSD 可通过应用覆盖指定深浅。活动窗口描边略清晰，非活动窗口更克制。

外框档位：`none`、`small`、`thick`。UI 显示“无／小边框／粗边框”，具体宽度在高级设置中可调。建议起始宽度为 0／4／10 个逻辑像素，最终通过内容安全几何和视觉评审确认。

安全留白是独立项；保护模式所需留白超过所选外框宽度时，应显示有效留白及原因，不能暗中把“小边框”渲染成任意宽度。自动留白可基于曲线计算，手动值不足时需提示并约束，或者要求切换紧凑模式。

颜色分为外框填充和轮廓线，避免“边框颜色”混指两者：

- `theme`：跟随当前 KOS 明暗主题的中性表面与轮廓色。
- `themePair`：用户指定浅色、深色两套颜色，随主题切换。
- `fixed`：使用单个固定颜色。

活动与非活动轮廓可有不同透明度。主题由项目现有外观来源提供有效颜色；插件不应各自推测当前明暗主题。主题切换不覆盖用户保存的固定颜色。

## 8. 配置模型与应用覆盖

建议持久化路径为 `~/.config/kos/window-appearance.json`，使用版本字段与递增修订号。下面是语义示例，具体字段及默认值在第一阶段冻结：

```json
{
  "version": 2,
  "revision": 1,
  "enabled": true,
  "defaults": {
    "corners": { "radius": 20, "profile": "continuous", "smoothness": 0.6 },
    "frame": { "mode": "none", "smallWidth": 4, "thickWidth": 10 },
    "content": { "mode": "protect", "padding": "auto" },
    "fill": { "mode": "theme" },
    "outline": { "width": 1, "widthUnit": "physical", "appearance": "auto", "colorMode": "theme", "light": "#FF000000", "dark": "#FFFFFFFF", "activeOpacity": 0.09, "inactiveOpacity": 0.045 },
    "shadow": { "enabled": true, "dynamic": true, "strength": 0.32, "minimumStrength": 0.08, "depthDecay": 0.7, "transitionMs": 180, "contactBlur": 1, "activeBlur": 14, "inactiveBlur": 8, "contactOpacity": 0.22, "ambientOpacity": 0.28 },
    "states": { "fullscreen": "inherit", "maximized": "inherit", "tiled": "flattenTouchingEdges" }
  },
  "apps": {
    "org.kde.kate": {
      "frame": { "mode": "thick" },
      "fill": { "mode": "themePair", "light": "#FFF0F2F5", "dark": "#FF24262A" }
    }
  }
}
```

所有颜色统一使用 `#AARRGGBB`，UI 提供颜色与透明度控件。曲线、强度、尺寸、时间、应用键有明确合法范围。非法配置拒绝写入并报告具体字段；现有有效状态不丢失。

应用覆盖是稀疏字段覆盖：缺失表示继承，`0`、`false`、`none` 是明确值。合并顺序为产品默认 → 全局用户设置 → 应用覆盖 → 必要的窗口状态约束。每个项目可以恢复继承，整应用可清除覆盖。

应用身份采用项目现有桌面应用标识与窗口身份解析；Wayland 和 XWayland 的 class/name 差异通过别名处理。初版不依赖窗口标题匹配，避免标题变化导致规则漂移。无法识别的窗口使用全局默认，并可从实时窗口选择器建立明确规则。

解析模块可同时编译进桥接特效和装饰器，不依赖 QML，不重复维护默认值。文件原子写入，目录监听处理文件替换，配置按修订号更新。主题的有效调色板作为运行状态传递，不频繁重写用户配置。

## 9. 设置页与运行通路

页面建议在现有外观体系内增加“窗口外观”，避免独立应用直接 import Shell 模块：

1. 总开关、当前生效状态和统一预览。
2. 无／小／粗边框、内容模式和安全留白说明。
3. 圆角半径、曲线预设与连续程度。
4. 外框颜色、轮廓线和明暗主题颜色。
5. 动态阴影参数及三个重叠窗口的层次预览。
6. 最大化、全屏、平铺与降低动态效果设置。
7. 应用覆盖列表、添加／删除、继承标记与恢复默认。

预览使用共享轮廓算法，提供带角落文字／按钮的直角内容示例，使保护与裁剪差异可见。预览与真实渲染有差异时必须标明，不能通过预览假装已经修改真实应用。

新增有边界的平台操作，如 `windowAppearance.get/update/status`；更新采用基于修订号的字段补丁，避免多个设置页覆盖彼此。平台校验及原子写入后通知组件，设置页取得已保存值、已应用修订号和错误。

滑块先本地预览，约 60–100 ms 合并运行更新，落盘使用较长防抖或交互结束写入。主题切换、文件写入和重配置不得阻塞 KWin 绘制线程。

装饰器接收 `kos-bridge` 传递的有效圆角与共享原生阴影，不重复决定策略或维护另一套配置；`kos-bridge` 接受配置重载与窗口有效调色板更新。具体 D-Bus 操作需可验证、限定参数，不借用按钮调试接口。参数更新不替换二进制，所以可即时生效。

## 10. 窗口状态与动画一致性

- 全屏默认继承圆角和内侧描边，允许全局及每应用配置关闭。阴影超出输出边界的部分自然被裁掉，不为显示阴影缩小全屏内容。圆角露出后方内容时需要合成，不能同时要求整个矩形全屏缓冲直接扫描输出。
- 最大化默认方角并收起额外边距；尊重工作区，不侵入系统栏。
- 平铺依据真实相邻边界压平接触角；不能仅凭窗口靠近屏幕边缘就当作平铺。
- 移动、缩放、跨屏时保持内容、曲线、按钮、轮廓和阴影同一几何。
- Dock 开启／最小化动画、概览等变换中保持一致；当前按钮“变换时隐藏”的策略不能直接套到整个外观。
- 验证效果链顺序与离屏重定向冲突，避免按钮被重复画、阴影被圆角裁掉，或 Glass 在透明角落留下材质。
- 关闭功能、切换装饰器、应用退出、插件销毁时恢复受修改的状态并释放缓存。恢复逻辑处理期间应用自身的状态变更，不能用过期快照覆盖新状态。

## 11. 兼容与升级诊断

运行状态区分：已保存、已应用、插件不可用、插件版本不匹配、等待重新登录、部分应用不支持所选模式。

配置协议版本独立于 KWin ABI。已有 `kosctl` 的 KWin 接口版本戳机制继续使用；开发参数不会要求重新编译，更新插件二进制仍需要安全的会话重启。禁止热卸载并重载被替换的插件 `.so`。

在确定支持范围后建立组合矩阵，至少覆盖本机升级前后 Qt 6.11.2／6.12.0 的数据通路与 KWin 6.7.4／6.7.5 的匹配构建。可运行组合必须使用匹配依赖，不能将版本号任意拼成不存在的发行环境。Nix 构建也需使用其自己的 KWin 头文件和运行环境验证。

跨 QML 信号、IPC 和 C++ 的集合转换统一做兼容验证，包含嵌套数组、空数组、`null`、布尔值和应用覆盖。更旧版本只有通过构建与行为验证后才列为支持；声明 Qt 编译最低版本不代表所有旧版 KWin API 都兼容。

## 12. 开发阶段与完成标准

### 阶段 A：可行性原型与接口冻结

验证连续裁剪、效果链、遮挡／不透明区域、自绘阴影处理、两类窗口真实外框留白和输入几何。产出运行样例、支持范围及失败原因。冻结配置、应用身份、曲线与颜色语义。

完成标准：能证明哪些窗口可无损保护；不支持部分有明确策略和提示。若需要修改 KWin，先形成独立工作项与范围，不能藏在设置页实现里。

### 阶段 B：共享配置与 Settings 页面

实现配置解析／合并／迁移、原子存储、平台操作、运行状态、全局设置与应用覆盖页面、离线预览。初期插件功能尚未实现的项显示真实状态，避免“保存成功”被误认为“效果已生效”。

完成标准：重启后设置保留；应用覆盖只影响指定字段；主题颜色正确；错误写入不破坏旧配置；多个更新不丢字段。

### 阶段 C：统一轮廓、外框和内容模式

扩展 `kos-bridge` 窗口外观模块，接入装饰器布局，处理圆角／描边／外框，调整 Glass 普通窗口路径。实现 A 阶段已经证明成立的内容保护方式。

完成标准：系统装饰及支持的自绘窗口使用一致轮廓；三档外框和每应用设置正确；保护模式不裁角落内容；点击、拖动、缩放坐标一致；禁用后恢复。

### 阶段 D：动态阴影与动画

实现原有阴影接管、遮挡层级、焦点过渡、缓存和重绘；处理 Dock 变换、概览、多屏和平铺。

完成标准：无双重阴影；后方阴影按规则减淡；焦点切换连续；阴影不穿透前方窗口；动画中外观无脱离或残影。

### 阶段 E：兼容、性能与交付

完成多版本组合测试、真实应用回归、运行诊断、打包与文档。只有相关验证通过才将功能设为默认启用。安装更新时明确提示会话重启，交付时移除／关闭独立圆角特效的步骤应在新功能验证通过之后进行。

## 15. 核心验收结论

最终交付必须能够回答：这个窗口使用哪条应用规则、哪个内容模式、哪种曲线、哪个阴影层级、配置是否真正生效。用户能从 kos-settings 修改并即时看到变化；内容保护和不支持情况必须可解释。统一外观不能以静默裁掉内容、改变点击位置、重复阴影或破坏窗口动画为代价。
